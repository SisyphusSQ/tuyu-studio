## 目标

本计划把图屿设计拆成可实施、可验收、可回归的生产切片。每个切片都要形成真实能力闭环，而不是只完成静态界面或单点演示。

## 交付切片

| 顺序 | 切片 | 产出 | 前置 |
| --- | --- | --- | --- |
| 1 | 本地项目与存储 | 项目创建、打开、保存、锁、健康检查 | 无 |
| 2 | Creative Graph 基础 | 节点、边、布局、Inspector、自动保存 | 切片 1 |
| 3 | 资产库与绑定 | 文件导入、digest、缩略图、角色/场景/道具绑定 | 切片 1-2 |
| 4 | 剧本与分镜 | Script、Scene、Shot、手动拆分、字段校验 | 切片 1-3 |
| 5 | 指令栈预览 | 项目原则、上下文解析、能力包、输出契约 | 切片 2-4 |
| 6 | AI 任务运行 | 结构化文本任务、图像任务、PromptRun、错误语义 | 切片 5 |
| 7 | 生成交接包 | Shot/Scene 导出、manifest、参考图、清单、校验 | 切片 3-6 |
| 8 | 结果回收与 review | 结果导入、VideoResult、take、状态、评审 | 切片 7 |
| 9 | 安全与可观测 | 路径守卫、审计、健康检查、恢复、脱敏报告 | 横向贯穿 |
| 10 | 项目迁移与稳定性 | schema 迁移、备份、导出、跨目录打开 | 切片 1-9 |

## 生产完成定义

一个切片完成必须同时满足：

- 用户路径能走通，且不是只靠开发者手工改文件。
- 数据落盘后重启应用仍能恢复。
- 失败场景有可读错误和恢复入口。
- 关键状态变更有审计或运行记录。
- 涉及文件写入时有路径守卫和相对路径策略。
- 对应设计文档有验收项被覆盖。
- 自动测试、手动验证或文档检查至少有一种稳定入口。

## 验收矩阵

| 能力 | 功能验收 | 数据验收 | 错误验收 |
| --- | --- | --- | --- |
| 项目创建 | 创建后进入空画布 | 目录、project、graph 文件存在 | 不可写目录提示失败 |
| 项目打开 | 打开已有项目并恢复视口 | schema 和健康检查通过 | 损坏文件触发恢复 |
| 节点编辑 | 创建、移动、删除、连线 | graph version 自增 | 非法边被拒绝 |
| 资产导入 | 拖入图片/视频并预览 | Asset、digest、缩略图存在 | 缺失文件可定位 |
| 连续性 | 锁定角色/场景规则 | 规则写入对象文件 | 冲突任务被阻断 |
| 剧本分镜 | 剧本拆场并生成 Shot | ScriptScene、ShotCard 存在 | 缺字段不能导出 |
| 指令预览 | 可查看编译指令 | ContextBundle 和 schema 可查 | 上下文过大有提示 |
| AI 任务 | 运行并产出结构化结果 | PromptRun 完整 | schema 错误不污染正式对象 |
| 图像生成 | 产出文件并入资产库 | 输出路径、digest、绑定存在 | 产物缺失返回错误 |
| 交接包 | 导出可检查包 | manifest 引用全部存在 | 绝对路径被拒绝 |
| 结果回收 | 拖入结果并绑定 Shot | VideoResult 和 take 存在 | 错绑可解绑 |
| 审计 | 关键操作可追溯 | events.jsonl 可读取 | 安全拒绝写入事件 |

## 测试层级

### 单元测试

| 模块 | 重点 |
| --- | --- |
| PathGuard | 路径清理、越界拒绝、符号链接策略 |
| ProjectStore | 原子写、备份、schema 迁移、恢复 |
| GraphDomain | 节点边校验、删除策略、版本冲突 |
| AssetLibrary | digest、重复检测、绑定、缺失检查 |
| InstructionCompiler | 编译顺序、data 包装、冲突检测、上下文摘要 |
| RuntimeGateway | 状态转换、超时、取消、错误映射 |
| PackageExporter | manifest、相对路径、引用完整性 |

### 集成测试

| 场景 | 步骤 |
| --- | --- |
| 项目重启恢复 | 创建项目、建节点、导入资产、关闭、重开、校验 |
| 资产到镜头 | 导入角色图和场景图，绑定 Shot，检查 context_ready |
| 指令任务 | 生成 PromptRun，校验 compiled、context、schema、output |
| 导出包 | 从 Shot 导出包，校验 manifest 和引用文件 |
| 结果回收 | 导入结果文件，绑定 Shot，切换 review 状态 |
| 健康检查 | 手动删除资产，运行检查，确认影响对象列表 |

### 手动验收脚本

每次生产验收至少走一遍：

1. 新建项目。
2. 导入一张角色参考图、一张场景参考图、一个结果视频占位文件。
3. 创建角色、场景和 Shot。
4. 绑定资产并锁定一条连续性规则。
5. 预览指令栈。
6. 运行一次结构化文本任务或使用 mock runtime 生成输出。
7. 导出 Shot 交接包。
8. 回收结果并标记 review。
9. 重启应用后确认所有对象、状态、路径和审计记录仍存在。

## 文档验收

设计文档本身需要保持：

- `architecture/` 只保留脱敏后的架构总览。
- `details/` 至少覆盖产品、存储、图谱、资产、剧本分镜、指令栈、运行时、前端、安全、测试。
- 不在正式设计稿中固化外部品牌或供应商名称。
- 不使用降级式交付口径。
- 所有路径示例使用占位或项目内相对路径。
- 每篇细节文档都有验收标准。

## 回归命令

仓库级验证沿用 harness：

```bash
make harness-check
make harness-review-gate PLAN=.agents/plans/2026-05-14-design-docs-production-refine.md
```

文档结构检查：

```bash
find docs/design -maxdepth 3 -type f -print | sort
```

正式设计稿敏感词检查由计划文件维护，执行时只扫描 `docs/design`，避免把源材料或计划中的历史引用误算为设计稿内容。

## 发布前检查

| 检查 | 标准 |
| --- | --- |
| 目录结构 | 设计文档、测试 runbook、issue 说明路径稳定 |
| 示例数据 | 示例不包含真实用户素材、凭据、本机路径 |
| 交接包 | 包可复制到另一目录检查 |
| 错误提示 | 关键失败都有用户可读信息 |
| 审计 | 运行、导出、回收、删除都有记录 |
| 恢复 | 崩溃、中断、迁移失败有恢复路径 |
| 替换能力 | provider profile 和 adapter 可以替换，不破坏核心对象 |

## 后续 issue 拆分建议

后续如果要从设计进入实现，建议按交付切片创建执行 issue。每个 issue 正文应包含：

- Goal
- Scope
- Out of Scope
- Implementation Scope
- Acceptance Criteria
- Verification Commands
- Data / Schema Impact
- Security and Recovery Notes

不要只用标题或摘要创建 issue，否则容易遗漏错误语义、状态推进、文档同步和验收口径。
